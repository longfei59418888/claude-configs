# Figma 组件开发规范

> 适用范围：基于 Figma 设计稿编写前端页面、组件、样式与静态资源时。
> 强制级别：**MUST（必须）** / **SHOULD（应当）** / **MUST NOT（禁止）**。
> 本规范用于约束设计稿还原、组件抽象、资源处理、可访问性、TypeScript 与性能，不替代项目已有目录结构、命名、Lint、格式化与 UI 技术栈规范。

---

## 0. 首要原则

1. **MUST** 先识别当前项目使用的技术栈、组件库、样式方案、主题变量、目录结构与命名规范，再开始实现。
2. **MUST** 基于 Figma 设计稿完成组件编写，按设计稿一比一还原布局、间距、字号、层级、状态、交互与资源，禁止脱离设计稿自行发挥。
3. **MUST** 优先复用项目已有组件、hooks、工具函数、主题变量与样式规范，不重复造轮子。
4. **MUST NOT** 在组件中硬写 mock 数据、臆测接口字段、臆测业务数据结构或自行编造接口返回。
5. **MUST** 遵循 TypeScript strict 要求，不使用 `any` 逃避类型约束，除非项目既有规范允许且有明确理由。

---

## 1. Figma 设计稿还原

- **MUST** 使用 Figma 设计稿作为唯一视觉来源，严格还原组件尺寸、间距、颜色、字体、圆角、边框、阴影、图标、图片、层级与响应式表现。
- **MUST** 对齐设计稿中的组件状态，包括 default、hover、active、disabled、loading、empty、error、selected、focused 等状态。
- **MUST** 按项目现有技术和规范选择合适的布局与样式写法，例如 CSS Modules、styled-components、Tailwind CSS、Sass、组件库 token 或主题变量。
- **MUST NOT** 在没有依据的情况下改变布局结构、视觉风格、交互方式或信息层级。
- **SHOULD** 在实现前检查 Figma 中是否已有组件实例、Variant、Auto Layout、Design Token 或样式变量，并优先映射到项目现有组件和变量。

---

## 2. 布局与样式

- **SHOULD** 优先使用 Flex、Grid、组件库布局能力或 Figma Auto Layout 对应的 CSS 实现。
- **SHOULD NOT** 优先使用 `position: absolute` 搭建常规布局；仅在角标、浮层、装饰定位、覆盖层等确有必要的场景使用。
- **MUST** 响应式布局与断点遵循项目既有规范，不自行新增不一致的断点体系。
- **MUST** 尽量使用项目已有变量、主题 token、CSS 变量、设计 token 或 Tailwind 配置，不直接硬写颜色和尺寸。
- 如果项目使用 Tailwind CSS，**MUST** 遵循 Tailwind CSS 规范：
  - 优先使用配置中的 theme token、spacing、color、fontSize、radius、shadow。
  - 禁止大量使用任意值类名规避设计系统，确有必要时保持局部、可解释。
  - 复杂重复样式应抽成组件或复用 class 组合，不在多处复制。
- **MUST** 确保文本不溢出、不遮挡、不与其他 UI 元素重叠；必要时使用换行、省略、最小宽度、最大宽度或响应式布局处理。

---

## 3. 静态资源与图片

- **MUST** 使用 Figma 中真实设计资源，禁止用无关占位图替代正式视觉资源。
- 当需要下载图片时，**MUST** 下载渲染尺寸的 2 倍图，图片源尺寸约束在实际渲染尺寸 2 倍以内，避免引入无损压缩的大体积原图。
- **MUST** 将下载后的位图资源转为 WebP 格式后在页面中使用，除非项目已有资源规范要求其他格式，或图片格式本身不适合 WebP。
- **MUST** 按项目静态资源目录规范存放图片，并使用清晰、可追踪的命名。
- **MUST** 为 `img` 设置准确的 `alt`；装饰图片可使用空 `alt=""`，但必须符合项目可访问性规范。
- **SHOULD** 根据场景使用 `loading="lazy"`、响应式图片、尺寸声明、CDN 参数或项目图片组件来降低加载成本和布局偏移。

---

## 4. 组件抽象与复用

- **MUST** 开发前检查项目中是否已有相同或近似组件，优先复用或扩展既有组件。
- **MUST** 当出现重复 UI 结构、重复交互逻辑或重复样式时进行抽象：
  - 重复组件必须抽成 Component。
  - 同类逻辑重复三次及以上必须抽成 Hook。
- **MUST** 按项目目录结构放置通用组件、页面私有组件、hooks、类型与样式文件。
- **MUST** 组件 props 设计清晰、类型明确，不把业务接口响应直接泄漏为展示组件的全部输入，除非项目已有模式如此。
- **MUST NOT** 为了局部实现引入不符合项目风格的新抽象、新状态管理方式或新样式体系。

---

## 5. 命名与类型

- **MUST** 文件名、目录名、组件名、变量名、hooks 名、类型名遵循项目现有命名规范。
- **MUST** React 组件、hooks、工具函数、类型定义与常量拆分方式遵循项目既有约定。
- **MUST** 所有 props、状态、事件处理、接口字段映射都有明确 TypeScript 类型。
- **MUST NOT** 忽略 TypeScript strict 报错，不通过类型断言掩盖真实空值、可选字段或不一致数据结构问题。

---

## 6. 可访问性

- **MUST** 所有 `button` 或可点击控件具备可识别名称；纯图标按钮必须提供 `aria-label`，第三方组件已内置可访问性能力的除外。
- **MUST** 所有 `img` 必须有 `alt`，第三方图片组件按其项目封装规范处理。
- **MUST** 表单控件、弹窗、菜单、Tab、Tooltip、Popover 等交互元素遵循项目已有可访问性实现方式。
- **SHOULD** 保留键盘可访问性、焦点态、语义标签与合理的 DOM 顺序，不用纯视觉结构破坏可读性。

---

## 7. 性能约束

- **SHOULD** 图片按需添加懒加载、明确宽高或使用项目图片优化组件，避免布局偏移和无谓带宽消耗。
- **SHOULD** 长列表、大数据表格或高频滚动区域使用虚拟列表、分页或增量渲染。
- **SHOULD** 动画优先使用 `transform`、`opacity` 等 GPU 友好属性，避免频繁触发布局和重绘。
- **MUST** 避免无意义的组件重复 render；按项目习惯使用 `memo`、`useMemo`、`useCallback`、状态下沉或状态拆分，但不要为了形式化优化增加复杂度。
- **MUST NOT** 在 render 阶段执行昂贵计算、创建不稳定大对象、直接触发副作用或发起请求。

---

## 8. 数据与接口

- **MUST NOT** 将 mock 数据写死到组件里。
- **MUST NOT** 猜测接口路径、请求参数、响应字段、枚举值或业务含义。
- **MUST** 数据来自真实接口、上层 props、store、fixture 文件、测试 mock 或项目既有数据层，来源必须清晰。
- **MUST** 对接口字段缺失、空数组、空字符串、null、undefined、加载中和错误状态进行合理处理。
- **SHOULD** 展示组件保持纯粹，接口请求、数据转换、状态管理放到项目规定的数据层、页面逻辑层或 hooks 中。

---

## 9. 验收检查

提交前必须完成以下检查：

- 是否按 Figma 一比一还原，包括尺寸、间距、颜色、字体、状态、图片和响应式表现。
- 是否复用了项目已有组件、hooks、变量、样式规范和命名规范。
- 是否存在重复组件或三次以上重复逻辑且未抽象。
- 是否存在硬编码 mock 数据、猜测接口、猜测字段或组件内伪造数据。
- 图片是否按 2 倍图约束下载，并转为 WebP 使用。
- `button` 是否具备 `aria-label`，`img` 是否具备 `alt`。
- TypeScript strict、Lint、格式化与项目测试是否通过。
- 是否存在不必要的 `position: absolute`、无谓 re-render、大图未优化、长列表未处理等问题。
